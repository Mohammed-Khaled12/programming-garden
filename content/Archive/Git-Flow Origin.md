# First time git

نيجي للجد بقي , روح سطب جت لو علي لينكس غالبا هتلاقيه متسطب لوحده , عموما سطبه و اعمل حوار الكونفيج بالاسم و الايميل و تعالي نبدا بقي 

```bash
git init
```
الامر ده بيعمل تحويل "فولدر عادي" (محدش داري بيه) إلى "Git Repository" (فولدر متراقب ومحفوظ تاريخه).

لما تكتب `git init`، جيت مش بيعمل "سحر"، هو بيعمل حاجة ملموسة جداً:

- بيصنع فولدر مخفي اسمه **`.git`**.
    
- الفولدر ده هو "المخ" و "الخزنة".
    
- فاكر الـ Hash اللي أنت طلعته (`a724...`)؟ الهاشات دي كلها بتتخزن جوه الفولدر ده في مكان اسمه `objects`.

الامر ده استخدمه و انت جوا فولدر المشروع و تستخدمه مره واحده بس .

كده انا يدوبك قولت للجت الفولدر ده تبعنا بس لسه الفولدر untracked يعني الامر ده بيخلي جت يدوبك بس يشوف الملفات 
طب اعرف منين حاله الفولدر ؟

```bash
git status
```
ده الامر اللي بيقولي حاله الفولدر بتاعتي ايه , لو حطيت `s-` في الاخر هيختصرلي الكلام شويه
no commits yet --> يعني معندوش ولا سناب شوت او فيرجن يعني من الكود او الفولدر بتاعك ل

```shell
git ls-files
```
الامر ده بيعرض الملفات اللي موجودة في **"الـ Index"** (قائمة التتبع) بتاعة Git.

```shell
git ls-files -s
```
كده يوريك ال SHA كمان


طب كده انا بعرف اشوف الفايلات اللي جوا ال WD بتاعتي عادي و بعرف اشوف اللي في ال Staging Area من الامر اللي فوق , اشوف بقي اللي في الريبو ازاي ؟ 
بص هو مفيش طريقه مباشره الصراحه و الموضوع مش مهم اوي اصلا بس في طريقه من خلال لينكس

```shell
find .git/objects/ -type f
```

ازاي بقي نعمل Staging او نحول الفايل من untracked ل Tracked ؟
```shell
git add file.txt
```
or 
```shell
git add .
```
or
```shell
git add *
```
اما اقوله ادد فايل معين زي اول واحده او افوله ادد كله زي التانيه و التالته و كمان عادي اقدر استخدم ال Wildcard

طب ازاي اعرف نوع الفايل بقي اذا كان بلوب ولا غيره ؟

```shell
git cat-file -t SHAcode
```
طب لو عايز اعرف السايز؟

```Shell
git cat-file -s SHAcode
```

طب لو عايز اعرف الكونتنت؟

```Shell
git cat-file -p SHAcode
```

طب كل ده و انا سايب الفايل بتاعي في ال انديكس عايزين بقي ناخد الاسناب شوت و يبقي عندنا فيرجن في الريبو 

```shell
git commit -m "My first commit: added test.txt"
```
-  كلمه **`commit`**: نفذ الحفظ.
    
-  كلمه **`-m`**: اختصار **Message**. (لو نسيتها، Git هيدخلك في متاهة اسمها Vim Editor عشان تكتب الرسالة غصب عنك، فخليك في الـ `-m` أريح).
    
- **`"..."`**: دي "اللافتة" اللي بتتحط على التغيير ده. (مهمة جداً عشان لما ترجع للكود بعد سنة تعرف أنت كنت بتعمل إيه هنا).

 إيه اللي حصل دلوقتي "Under the Hood"؟

أول ما تدوس Enter، هتلاقي Git رد عليك بحاجة زي كده: `[master (root-commit) 8f3a1b2] My first commit...`

1. **الـ Hash:** جيت عمل ID مميز للعملية دي (مثلاً `8f3a1b2`).
    
2. **التنظيف:** المنطقة الخضراء (Staging) فضيت خلاص.
    
3. **الحفظ:** الملف `test.txt` بقى جزء رسمي من تاريخ المشروع (Repository).

لو جبت دلوقتي بعد ما عملت ادد و بعدها كوميت و رزحت تبص علي الاوبجيكتس هتلاقي علي الاقل3
واحد للبلوب و التاني للتري اللي هو الفايل هيراركي اللي هو الفايل ده جوا مين جوا مين جوا مين و كمان هتلاقي التالت ده اسمه واحد اسمه كوميت ده عباره عن غلاف بيغلف بيه الاوبيكتس اللي مع بعض في نفس الكوميت الاصلي بدل ما يتوهوا مع بقيت الاوبجيكتس يقولك مين كان مع مين كا باتش و هتلاقيه بيقول بيانات التعديل  اللي هو فلان كذا يوم كذا عمل تعديل و كتبلنا المسدج دي و يوصلك لاول تري اتعدلت اكنه بوك مارك يعني دي الطريقه اللي جت بيعرف بيها انهي شويه بلوبات و تريهات اتعدلوا مع بعض في مره واحده

 الامر ده بيقارن بين اللي عندك في ال WD و Staging Area 

|**الأمر**|**الطرف الأول (الجديد)**|**الطرف الثاني (القديم/المرجع)**|**امتى تستخدمه؟**|
|---|---|---|---|
|**`git diff`**|**Working Dir**|**Staging Area**|لما عايز تشوف "أنا هببت إيه دلوقتي ولسه مجهزتوش؟"|
|**`git diff --staged`**|**Staging Area**|**Last Commit**|لما تكون عملت `add` خلاص، وعايز تراجع قبل ما تعمل `commit` نهائي.|
|**`git diff HEAD`**|**Working Dir**|**Last Commit**|لما عايز تشوف التغيير كله (من ساعة آخر Save) مرة واحدة، سواء عملت add أو لأ.|


ده "الميكروسكوب" بتاع Git. 🔬

لو `git log` هو "فهرس الكتاب" اللي بيوريك العناوين، فـ `git show` هو إنك تفتح صفحة معينة وتقرأ التفاصيل اللي فيها.

الأمر ده بيجاوب على سؤال: **"إيه اللي حصل بالظبط في الكوميت دي؟"**

---

 1. لو كتبته لوحده (Default Behavior)



``` shell
git show
```

بما إنك محددتش عايز تشوف مين، Git بيفترض إنك عايز تشوف **آخر حاجة حصلت** (اللي هي `HEAD`).

**النتيجة هتكون "تقرير شامل" بيجمع حاجتين:**

1. **Metadata (بيانات العملية):** مين اللي عملها (Author)، امتى (Date)، والرسالة (Message) والـ Hash ID.
    
2. **Diff (التغييرات):** بيوريك الملفات اللي اتغيرت جوه الكوميت دي (زي ما شوفت في `git diff` بالظبط).
    

---

2. الاستخدام الهندسي (Specific Commit)

أنت كمهندس مش دايماً عايز تشوف آخر حاجة، أحياناً عايز تراجع "مصيبة" حصلت من أسبوع.

هنا بتحتاج الـ **Commit Hash** (الكود الغريب اللي زي `a7241...`).

**السيناريو:**

1. اعمل `git log` وخد أول 5-6 أرقام من الـ Hash بتاع أي كوميت قديمة.
    
2. اكتب:
    

    ```shell
    git show 8f3a1b
    ```
    
    _(هيجبلك تفاصيل اللحظة دي بالذات)._

|**`git show`**|بيعرض تفاصيل "حاجة خلصت واتحفظت".|"وريني الصفحة رقم 5 في الأرشيف كان مكتوب فيها إيه".|

# Branching

اعتبر نفسك في لعبه GOW مثلا انت عندك ال Save الاساسي بتاعك اللي اللعبه بتعمله ده بنسميه Master branch 
انت تقدر تعمل سايف يدوي علشان تجرب استراتيجيه او خطه مثلا و لو فشلت عادي ترجع للسايف الاساسي ده بنسميه New Branch او تفرع جديد يعني

في جت البرانش هو موشر بيشاور علي كوميت معين , افراضيا انت بتبقي علي ال ماستر او الماين برانش 
لما بتعمل برانش جديد انت بتعمل بوينتر بيشاور علي نفس الكوميت اللي انت عليه بس لسه متحركش 

علشان تعرف انت عندك كام برانش ؟
```Shell
git branch 
```

علشان تعمل برانش جديد ؟
```shell
git branch branchName
```

انت كده عملت برانش جديد بس متنقلتش عليه لسه , انت لسه واقف علي الماستر طب اتنقله ازاي؟
```shell
git switch branchName
```

علشان تشوف التفرعات و كده ؟
```shell
git log --all --graph --oneline
```

---

كده عملت برانش و عملت في كوميتس و جربتها و عدلت و عاجبني و زي الفل عايز بقي ادمج اميرج البرانش ده مع الماستر 

اقف في المكان اللي عايز تدمج فيه و نادي علي اللي هتدمجه يعني لو عايز تجيب التعديلات من برانش اسمه Test و تحطها علي الماستر روح اقف في الماستر 
ندمج ازاي بقي ؟ في سياريوهين للدمج :

- Fast Forward Merge :
ده لو انت كنت شغال في البرانش الجديد و محدش لمس الماستر يعني الماستر زي ما هو قبل ما تعمل برانش هو هو لما عملت برانش اللي بيحصل ان جت مش بيعمل نقطه دمج جديده هو بس بياخد مؤشر الماستر يرميه قدام لحد اخر شغلك فكده بقي كله خط مستقيم اسمه الماستر 

- 3-Way / Recursive Merge:
لو انت شغال في البرانش بتاعك و في نفس الوقت حد عمل شغل علي الماستر اللي بيحصل ان جت بيعمل  عقده Knot تربط البرانشين ببعض بيعمل كوميت جديده اسمها Merge Commit بتجمع التغييرات من هنا و من هنا 
ليه اسمه 3-Way علشان هو بيبص علي ال 3 حاجات (اخر الماستر - اخر البرانش - نقطه التفرع المشتركه)

ازاي اعمل اميرج بقي ؟

متنساش --> اقف في المكان اللي عايز تدمج فيه و نادي علي اللي هتدمجه يعني لو عايز تجيب التعديلات من برانش اسمه Test و تحطها علي الماستر روح اقف في الماستر 

```Shell
git merge branchName
```

بعد الدمج تقدر تمسح البرانش القديم بقي 
```shell
git branch -d branchName
```

الامر ده بيعرفك مين معموله ميرجينج 
```shell
git branch --merged
```


ساعات بيحصل conflict و انا بدمج برانشين يكون مثلا الاتنين فيهم نفس السطر و كل حاجه بس ادخل انا اعدل في سطر و يبقي الاتنين مختلفين فلما اعمل ميرج جت ميعرفش ياخد مين و يديني كونفليكت , الحل الاسهل ادخل عدل فايل منهم 
شرح مختزل جدا دور في اكتر تاني

# Working With Remotes

بيبقي عندك ريموت ريبو يبقي مثلا في كوميتس و برانشز و هكذا اللي بتعمله انك تعمل كلون للريبو ده عندك تقدر بقي تزود عليه عندك و كده و بعدها تعمل push للتعديلات بتاعتك للريموت ريبو او تعمل pull(fetch) تجيب كل الابديتس من الريموت ريبو مثلا , تقدر تكونكت علي اكتر من ريموت عادي 
اغلب الوقت انت بتعمل الكلام ده علي هوستينج سيرفيس زي GitHub مثلا

ازاي اعمل كلون؟
```Shell
git clone URL_or_Location
```
كده هو هيعملي كلون عندي بنفس اسمها علي الريموت لو عايز اغير الاسم هكتب جنب ال URL الاسم اللي انا عايزه 

طب لو عايز اعرف اسماء السيرفرات اللي انا متصل بيها ؟
```SHELL
git remote
```
ده غالبا هيعرضلي كلمه Origin يعني احنا متصلين بسيرفر واحد اسمه اوريجين طب لو عايز اعرف تفاصيل اكتر ؟
```Shell
git remote -v
```
لو ركزت هتلاقي اوريجين متكرر مرتين مره جنبه fetch و مره جنبه push 

- push --> بترفع من عندك للسيرفر , بياخد الكوميتس من عندك و يرفعها علي سيرفر زي جت هاب علشان الناس تشوفها
- fetch --> تنزل ابديتس من السيرفر و ينزله في الملف المخفي اللي هو دوت جيت و مبيغيرش حاجه عندك تشوف الاول الابديتس و تقبلها عندك او لا 
- pull --> بيعمل فيتش و ميرج علي اللي عندك , مشكلته انه ممكن يكون في كونفليكت 

خلي بالك الكلونينج ممش مجرد داونلود انت بينزل عندك الملفات و كمان التراك هيستوري بتاعها

لو عايز تعرف البرانشز اللي جايه من الريموت ؟
```Shell
git branch -r
```

علشان اكونيكت علي كذا سيرفر بستعمل
```shell
git remote add <name> <url>
```
و غالبا النيم بيبقي اوريجين

لما تعمل كلون و تاخد الفايلز و كده و مثلا عملت برانش مش موجود في السرفر و خليت تعديلاتك فيه و تيجي تعمل push هيطلعلك ايرور علشان جت مش عارف يعمل سينك مع مين ماا البرانش ده مش موجود هناك 
الحل 
```shell
git push -u origin <branch_name>
```
هيكريت هناك برانش اسمه اللي انت حاطه و يسينك عليه الابديتس اللي اتعملت علي البرانش عندك 
علشان تعرف كل حاجه في حاجه هناك بتوازيها ولا لا 
```shell
git branch -vv
```
