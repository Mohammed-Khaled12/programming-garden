
# The Standard Streams

لما بتشغل أي أمر أو سكريبت، الكيرنال بيفتحله 3 قنوات اتصال وهمية (Streams) وبيديلهم أرقام تعريفية اسمها **File Descriptors (FD)** عشان البرنامج يعرف يستقبل داتا، ويطلع نتايج، ويبلغ عن المشاكل.

| File Descriptors (FD) |   Name   |       Function        | Default  |
| :-------------------: | :------: | :-------------------: | :------: |
|           0           | `stdin`  |     recives data      | Keyboard |
|           1           | `stdout` |   output/print data   | Teminal  |
|           2           | `stderr` | output error messages | Teminal  |

طب لو عايز اغير ال Default مثلا بدل ما اعرض علي التيرمينال اعرض علي فايل و هكذا ؟

# I/O Redirection

الـ Redirection هو إنك بتتدخل في شغل الكيرنال وتقوله: "غير المسار الافتراضي للـ FD ده، ووجهه لملف تاني". بنستخدم علامات أكبر من وأصغر من للتحكم ده:
#### 1. توجيه المخرجات السليمة (`>`) و (`>>`)

إنت هنا بتتعامل مع الـ `stdout` (رقم 1)، وبتحوله من الشاشة لملف.

- **الاستبدال (Overwrite `>`):** بيمسح أي داتا قديمة في الملف ويكتب النتيجة الجديدة. 

```bash
echo "First Line" > file.txt
```


- **الإضافة (Append `>>`):** بياخد النتيجة الجديدة يلزقها في آخر الملف من غير ما يمسح القديم (وده اللي بنستخدمه دايماً في تجميع الـ Logs).

```bash
echo "Second Line" > file.txt
```

#### 2. توجيه المدخلات (`<`)

بتقول للبرنامج بدل ما تستنى اليوزر يكتبلك على الكيبورد (`stdin` رقم 0)، اقرأ الداتا بتاعتك من الملف ده.

```bash
sort < unsorted_names.txt
```
(هنا برنامج `sort` هياخد الأسماء من الملف، يرتبها، ويطبعها على الشاشة).

#### 3. توجيه الأخطاء فقط (`2>`) و (`2>>`)

هنا إحنا بنستخدم رقم الـ FD بتاع الـ Error اللي هو `2` تحديداً قبل السهم، عشان نعزل الأخطاء عن النتايج السليمة.

```bash
ls -l /root /home 2> errors.log
```

الأمر هيطبع محتويات `/home` (عشان دي نتيجة سليمة `stdout`) على الشاشة قدامك. لكن لما ييجي يدخل `/root` ويديلك `Permission denied` (عشان ده خطأ `stderr`)، مش هيطبعه على الشاشة، هيروح يرميه بصمت جوه ملف `errors.log`. _(وطبعاً لو استخدمت `2>>` هيعمل Append للأخطاء)._

#### Tricks

##### الحركة الأولى: دمج الصح والغلط في مكان واحد (`2>&1`)

لو بتعمل Backup سكريبت، أنت عايز تسجل كل حاجة (النجاح والفشل) في ملف Log واحد عشان تراجعه بعدين.

```bash
./backup_script.sh > full_backup.log 2>&1
```

`> full_backup.log` : وجه المسار رقم `1` (`stdout`) للملف ده.
`2>&1` : خد المسار رقم `2` (`stderr`)، ووجهه لنفس الـ Address اللي بيشاور عليه رقم `1`. (علامة `&` هنا بتفهم التيرمينال إن `1` ده رقم الـ FD، مش ملف اسمه 1).
(ملحوظة: في نسخ الـ Bash الحديثة والـ Zsh، بقوا بيختصروها كده: `&> full_backup.log` بتعمل نفس الوظيفة بالظبط).

##### الحركة التانية: الثقب الأسود (`/dev/null`)

ملف `/dev/null` ده عبارة عن ملف وهمي في لينكس (Black Hole). أي داتا بتتبعتله بتتمسح فوراً وتختفي من الوجود ومابتاخدش أي مساحة. بنستخدمه لما نكون بننفذ أمر هيطلع كمية أخطاء مزعجة إحنا مش مهتمين بيها ومش عايزينها لا على الشاشة ولا في ملف.

```bash
find / -name "secret_key" 2> /dev/nullv
```
دور في السيستم كله على الملف ده. النتيجة الصح اعرضها على الشاشة، وأي سطر يطلع فيه خطأ (زي إنك معكش صلاحيات تقرأ الفولدر ده) ارميه في الثقب الأسود وماتوريهوليش.
