# 1️⃣ Git Architecture & Philosophy

### ازاي Git بيتراك التغيرات بتاعتك؟ (Snapshot vs Delta)
الاول في البرامج التانية (زي SVN وغيره) --> اللي بيحصل إن أول ما تعمل مشروعك بياخد منه "سناب شوت" (صورة من الأصل)، وبعدين أنت بقي كل ما تغير سطر، يقوم هو حافظ **السطر الجديد بس** في النسخة اللي بعديه (Delta).

**عكس Git تماماً:**
أنت لو غيرت "حرف" بس في الأصل، Git بياخد **Snapshot من كل حاجة عندك** مع كل تغيير.
* عندي فايل رافعه Git، وجيت بكره زودت `semicolon`.. يقوم Git واخد سناب شوت من أول وجديد للفايل كله.

---

### هي إيه كانت الـ Requirements بتاعة الاركيتيكت؟
"إيه اللي كانوا عايزينه من Git أصلاً؟"

1.  **Content Tracking:** السيستم يتراك كل حاجة حرفياً، سواء فايل أو فولدر، ويتراك كل حاجة فيهم (الكونتنت + الميتا داتا زي اسم الفايل وحجمه ونوعه).
2.  **Integrity:** مينفعش يعدلي علي الكونتنت ويكتبلي مثلاً جوا إنه اترفع إمتي أو اتعدل إمتي (No content change hidden inside files).
3.  **Portable:** لازم يكون **OS independent**، يشتغل علي أي نظام (Linux, Windows, Mac).
4.  **Unique ID:** كل "Object" (أي حاجة Git هيتابعها) لازم يبقي ليه معرف فريد محدش زيه.
5.  **History & Log:** مش بس تحطلي الفيرجنز القديمة.. أنا محتاج أعرف مين كان الأول؟ ومين بعديه؟ وحصل إيه؟ ولو حد عدل ورجع لفيرجن قديم يبان.

---

### نطبق الـ Requirements دي ازاي؟ (Git Objects)

**1. مشكلة الاسم:**
حوار إن الفايل يبقي اسمه في الـ Working Directory `a.txt` ويروح في الريبو باسمه `a.txt` دي متنفعش وتعارض أول ريكوايرمينت. ليه بقي؟
علشان أنا أصلاً عايز أتراك الاسم.. افرض اتغير؟ اتمسح؟ اتنسف؟

**الحل:**
قالك إن جوا Git كل حاجة هتبقي **Objects**.
إيه بقي الـ **Git Objects** (الحاجات اللي Git بيعملها تراك)؟

1.  **Blob:** ببساطة هو "الفايل"، بس المرة دي بتابع الكونتنت والميتا داتا (من غير الاسم).
2.  **Tree:** ببساطة هو "الفولدر"، بس المرة دي بتابع الكونتنت والميتا داتا، وعلشان أنا بتابع الاتنين، الفولدر مبقاش فولدر خلاص.. بقي Object فيه بيانات الفولدر ده واسمه Tree.
3.  **Commit:** الغلاف اللي بيلم الليلة دي وبيقول مين عمل إيه وامتى.
4.  **Annotated Tag:** (هيجيلها شرح قدام).

> **الخلاصة:** احنا حلينا أول نقطة بإننا نحول الفايل من الشكل القديم لـ Object عشان نحط فيه الكونتنت والميتا داتا ونتراكهم.

---

**2. مشكلة الـ Portability:**
علشان يبقي OS independent محتاجينه يبقي **Simple Folder Structure**.
يعني فولدر يتحط في أي حتة يتقري، مش داتا بيز معقدة تشتغل علي أنظمة معينة.
* **الحل:** الريبو ده يبقي جوا الـ Working Directory شخصياً، ويكون فولدر اسمه `.git` ويكون Hidden.
    * كده لما تنقل الفولدر ده من أي حتة لأي حتة، هتنقله بتعديلاته وهيشتغل في كل حتة.

---

**3. مشكلة الـ Unique ID (Hashing):**
كده مفيش فايل وفولدر.. بقوا Blob و Tree. ندخل في تالت مشكلة: عايز Identifier بقي!
أسماء الملفات دي مبقتش نافعة (دي بتتغير وأنا بتراكها أصلاً). طب نحل المشكلة ازاي؟

في طرق كتيرة بس هنقول واحدة اسمها: **Hash Function / Algorithm**.
والله دي دالة بتاخد أي بيانات (فايل، نص، حرف) وتطلعلي "قيم ثابتة الطول" اسمها **Hash**.
* أي تغيير بسيط في المدخلات --> بيغير الهاش تماماً.
* وبكده كل حاجة هتبقي ليها Unique ID.
* أشهر الأنواع: `SHA-1` (بيطلع 40 حرف) ودلوقتي في `SHA-256`.

> [!WARNING] سر الهاش في Git 🔐
> روح جرب تعمل هاش لنص علي موقع أونلاين أو علي التيرمينال، وتعالي قارنه بهاش Git لنفس النص.. **هتلاقيه مختلف!**
>
> **ليه؟**
> لأن Git قبل ما يعمل Hash، بيزود **"مقدمة" (Header)** خفية شكلها كده:
> `blob <size_of_content>\0` + `Content`
> بيزود التايب والسايز و Null Character وبعدها الكونتنت.

**لو عايز تطلع نفس الهاش بتاع Git بالظبط من التيرمينال:**
```bash
echo "Text" | git hash-object --stdin
```

يبقي كده كل لما تيجي تباصي أي حاجة لـ Git، هيقوم ياخد الكونتنت ويزود عليها التايب والسايز ويعمل الـ SHA بتاعها علشان يتأكد إن مفيش تغيير. (Integrity).

# 2️⃣ The Three-Tree Architecture 🌲🌲🌲

خد بالك إن الـ Version Control اللي قبل Git كانوا شغالين بنظام اسمه **Two-Tree Arch**:

1. **Working Tree:** اللي بتشتغل عليه.
    
2. **Repo:** اللي فيه الفيرجنز.
    

- (تعدل علي الـ WT وتبعت علي الريبو).
    

**هل بقي Git شغال Two-Tree؟**

هممم لا.. Git شغال بـ **Three-Tree Architecture**.

![[Pasted image 20260201211530.png]]

1. **Working Directory (WD):** ده الفولدر اللي أنا شغال فيه علي جهازي بكتب كود فيه، أي تعديل هنا مش محفوظ أو متسجل (زي مثلاً فايل `main.cpp`).
    
2. **Staging Area (Index):** منطقة "التحضير" للكوميت. Git بياخد نسخة من الـ Working ويحطها في الـ Staging ويقول "ده اللي هيتعمله كوميت". تقدر تضيف أو تشيل فايل أو تعمل كوميت جزئي.
    
    - _ميزتها:_ ممكن أجمع عدد من التعديلات وأعملها كوميت مرة واحدة علي فيرجن واحد بدل ما يبقي عندي مليار فيرجن.
        
3. **Repository:** ده بعد التسجيل بقي (الخزنة).
    

---

### إزاي بنعمل Snapshot؟ (التسلسل الطبيعي)

إيه ده هو أنا بحط في الريبو SHA1 أو Blob وخلاص؟

كده اتعمل تراكينج وبنقارن الـ SHAs بس مفيش "Version 1" لسه!

طب هيتعمل إمتي؟ لما أستعمل أمر `git commit`.. دي اللحظة اللي بيتعمل فيها أول سناب شوت.

**التسلسل:**

`git add` --> Stage Files (تجهيز)

`git commit` --> New Version in Repo (اعتماد)

# 3️⃣ First Time Git (Commands & Hands-on)

نيجي للجد بقي. روح سطب Git واعمل حوار الكونفيج بالاسم والايميل وتعالي نبدأ.

### 1. البداية

``` shell
git init
```

الأمر ده بيعمل تحويل "فولدر عادي" (محدش داري بيه) إلى "Git Repository" (فولدر متراقب ومحفوظ تاريخه).

Git مش بيعمل سحر، هو بيعمل حاجة ملموسة جداً:

- بيصنع فولدر مخفي اسمه `.git`.
    
- الفولدر ده هو "المخ" و "الخزنة".
    
- فاكر الـ Hash اللي أنت طلعته؟ الهاشات دي كلها بتتخزن جوه الفولدر ده في مكان اسمه `objects`.
    

### 2. الاستكشاف

كده أنا يدوبك قولت للـ Git الفولدر ده تبعنا، بس لسه الفولدر Untracked.

طب أعرف منين حالة الفولدر؟

``` shell
git status
```

- `no commits yet`: يعني معندوش ولا سناب شوت لسه.
    

عشان أشوف الملفات الموجودة في **"الـ Index"** (قائمة التتبع) بتاعت Git:

``` shell
git ls-files    # يعرض الاسماء
git ls-files -s # يعرض الـ SHA كمان
```

### 3. التدوير في الخبايا (Advanced) 🕵️‍♂️

أشوف بقي اللي في الريبو إزاي؟

مفيش طريقة مباشرة أوي، بس ممكن من خلال لينكس:

``` shell
find .git/objects/ -type f
```

### 4. التحضير (Staging)

ازاي أحول الفايل من Untracked لـ Tracked؟

```shell
git add file.txt  # فايل معين
git add .         # كله
git add * # كله (Wildcard)
```

**سؤال وجودي:** إزاي أعرف نوع الفايل بقي إذا كان Blob ولا غيره؟ (Cat File)

``` shell
git cat-file -t SHAcode  # Type (blob, tree, commit)
git cat-file -s SHAcode  # Size
git cat-file -p SHAcode  # Print Content (يوريك الكلام اللي جوا)
```

### 5. التسجيل (Commit)

كل ده وأنا سايب الفايل في الانديكس.. عايزين بقي ناخد السناب شوت ويبقي عندنا فيرجن في الريبو.

``` shell
git commit -m "My first commit: added test.txt"
```

- **`commit`**: نفذ الحفظ.
    
- ال **`-m`**: اختصار Message (لو نسيتها هيدخلك في متاهة Vim).
    
- **`"..."`**: اللافتة اللي بتتحط علي التغيير.
    

**Under the Hood (إيه اللي حصل؟):**

أول ما تدوس Enter:

1. **الـ Hash:** جيت عمل ID مميز للعملية دي (Commid ID).
    
2. **التنظيف:** منطقة Staging فضيت خلاص.
    
3. **الحفظ:** الملف `test.txt` بقي جزء رسمي من تاريخ المشروع.
    

> لو رحت تبص علي الـ Objects دلوقتي هتلاقي علي الأقل 3:
> 
> 1. واحد للـ **Blob** (الفايل).
>     
> 2. واحد للـ **Tree** (الفايل هيراركي).
>     
> 3. واحد للـ **Commit** (الغلاف اللي بيغلف الاوبجيكتس ويقولك مين مع مين كا "باتش"، وبيشيل بيانات التعديل والوقت).
>     

أعرف منين الكوميت اوبجيكت من وسط الـ 3؟

``` shell
git log
```

هيديك الـ SHA بتاع الكوميت، والكوميت هيوصلك للتري، والتري توصلك للبلوب.

# 4️⃣ Navigation & Time Travel ⏳

### ما هو الـ HEAD؟ 🤯

الـ HEAD بالضبط هو **Pointer** شايل الـ SHA بتاعت الكوميت اللي واقف عليه حالياً (أنت شايف إيه في الـ Working Directory).

- تسلسل الكوميتس اللي بيشاوروا علي البيرانت بتاعهم ده بنسميه **Branch** (باي ديفولت اسمه `master`).
    

### التحرك بين الفيرجنز

إزاي أتحرك؟ باني أحرك الهيد.

لو حركت الهيد ورا مثلاً بيبقي عندي اختيار من الاتنين:

1. أخليه يسمع مباشر في الـ WT وتتغير (خطير).
    
2. أخليه يسمع في الـ Staging بس (أمان عشان أراجع).
    

**الأوامر:**



```shell
git reset HEAD~1       # ارجع خطوة لورا (يسمع في Staging بس)
git reset --hard HEAD  # ارجع خطوة لورا (يسمع في WT مباشر - بيمسح الشغل)
```

- ممكن أغير الرقم `~2`, `~3` وهكذا.
    

> [!TIP] الصندوق الأسود: Reflog
> 
> حركة الهيد مش "Object" يعني مش هتبان في الـ Log العادي.
> 
> لو حركت الهيد لكوميت ورا.. الكوميت اللي قدامه مش هيبان معاك في اللوج (هو موجود متمسحش بس استخبي).
> 
> عشان تشوف كل تحركاتك:
> 
> `git reflog`

**إزاي أعمل Fast Forward (أطلع قدام تاني)؟**

جيب الهاش أو الرقم من الـ Reflog واستخدم:

``` shell
git reset HEAD@{1}
```

# 5️⃣ Comparisons (Diff & Show) ⚖️

### Git Diff (المقارنة الحية)

```shell
git diff
```

|**الأمر**|**الطرف الأول (الجديد)**|**الطرف الثاني (القديم/المرجع)**|**امتي تستخدمه؟**|
|---|---|---|---|
|`git diff`|**Working Dir**|**Staging Area**|لما عايز تشوف "أنا هببت إيه دلوقتي ولسه مجهزتوش؟"|
|`git diff --staged`|**Staging Area**|**Last Commit**|لما تكون عملت `add` خلاص، وعايز تراجع قبل ما تعمل `commit`.|
|`git diff HEAD`|**Working Dir**|**Last Commit**|لما عايز تشوف التغيير كله مرة واحدة.|
|`git diff sha..sha`|**Commit**|**Commit**|بيقارن اتنين كوميت ببعض (هات اللوج وقارن).|

### Git Show (الميكروسكوب) 🔬

لو `git log` هو "الفهرس"، فـ `git show` هو إنك تفتح صفحة وتقرأ التفاصيل.

بيجاوب علي سؤال: **"إيه اللي حصل بالظبط في الكوميت دي؟"**

1. `git show`: بيوريك تفاصيل آخر حاجة (`HEAD`). (Metadata + Diff).
    
2. `git show <SHA>`: بيوريك تفاصيل كوميت قديمة ومحددة.
    
3. `git show --stat`: بيوريك "ملخص" (فايل كذا زاد 3 سطور) من غير دوشة الكود.

# 6️⃣ Undoing Things (تظبيط الغلطات)

- **To Delete Repo (Opposite of init):**
    
    `rm -rf .git/`
    
- **To Untrack file (Remove from Staging only):**
    
    `git rm --cached filename`
    
- **To Discard Changes (Restore WD to match Index):**
    
    `git restore filename` (بيلغي التعديل اللي عملته في الفايل).
    
- **To Unstage (Return from Index to WD):**
    
    `git restore --staged filename` (بيلغي الـ Add).
    
- **Shortcut (Add + Commit):**
    
    `git commit -am "Message"`
    
- **Fix Last Commit Message:**
    
    `git commit --amend`

# 7️⃣ Branching & Merging 🌿

اعتبر نفسك في لعبة GOW.. عندك الـ Save الأساسي (Master).

تقدر تعمل Save يدوي عشان تجرب استراتيجية، لو فشلت ترجع (Branch).

- **Branch:** هو مؤشر بيشاور علي كوميت معين.
    
- لما بتعمل برانش جديد، أنت بتعمل بوينتر بيشاور علي نفس الكوميت اللي أنت عليها بس لسه متحركش.
    

### الأوامر الأساسية

``` shell
git branch              # اعرف عندي كام برانش
git branch branchName   # اعمل برانش جديد
git switch branchName   # انقلني عليه (حرك الـ HEAD)
git branch -d branchName # امسح البرانش (بعد الدمج)
git log --all --graph --oneline # شوف التفرعات رسم بياني
```

### Merging (الدمج)

**قاعدة ذهبية:** اقف في المكان اللي عايز تدمج فيه، ونادي علي اللي هتدمجه.

(عايز تجيب Test تحطه في Master؟ --> اقف في Master واكتب `git merge Test`).

**سيناريوهات الدمج:**

1. **Fast Forward Merge:**
    
    - لو أنت كنت شغال في البرانش الجديد ومحدش لمس الماستر.
        
    - Git مش بيعمل "نقطة دمج" جديدة، هو بس بياخد مؤشر الماستر يرميه قدام لحد آخر شغلك. (كله بقي خط مستقيم).
        
2. **3-Way / Recursive Merge:**
    
    - لو أنت شغال في البرانش، وحد تاني عمل شغل علي الماستر.
        
    - Git بيعمل "عقدة" (Knot) تربط البرانشين ببعض اسمها **Merge Commit**.
        
    - ليه اسمه 3-Way؟ لأنه بيبص علي 3 حاجات (آخر الماستر - آخر البرانش - نقطة التفرع المشتركة).
        

> **Conflict:** لو عدلت نفس السطر في البرانشين، Git هيديك Conflict. الحل الأسهل: ادخل عدل الفايل بايدك واختار النسخة الصح واعمل Commit.

# 8️⃣ Working With Remotes ☁️

بيبقي عندك **Remote Repo** (علي GitHub مثلاً).

اللي بتعمله إنك بتعمل **Clone** للريبو ده عندك، تقدر تزود عليه، وبعدها تعمل **Push**، أو تعمل **Pull** تجيب الابديتس.

### الأوامر والفرق بينهم

- `git clone <URL>`:
    
    مش مجرد داونلود.. ده بينزل الملفات + التراك هيستوري بتاعها.
    
- `git remote -v`:
    
    يوريك أنت متصل بمين (غالباً `origin`).
    
- `git remote add <name> <url>`:
    
    لو عايز تكونكت علي سيرفر جديد.
    

**الفرق بين التحديثات:**

1. **Push:** بترفع من عندك للسيرفر (بياخد الكوميتس بتاعتك يرفعها).
    
2. **Fetch:** بينزل الابديتس من السيرفر ويحطها في `.git` بس **مبيغيرش حاجة عندك في الفايلات**. (تشوف الأول وتقرر).
    
3. **Pull:** بيعمل Fetch + Merge في نفس الوقت. (بيطبق التغييرات فوراً).
    

**تنبيه هام في أول مرة:**

لو عملت برانش جديد عندك مش موجود في السيرفر وجيت تعمل Push هيطلعلك Error (مش عارف يعمل Sync مع مين).

الحل:

``` shell
git push -u origin <branch_name>
```

(بيكريت البرانش هناك ويسينك عليه).

# 9️⃣ Tags (الإصدارات) 🏷️

مش كل تعديل بتعمله وتحطه في الريبو بيبقي فيرجن جديد يستاهل رقم (زي v1.0).
علشان كده عندنا حاجة اسمها **Tags**، ودي ببساطة "ورقة ملاحظات" بتلزقها علي كوميت معين وتقول "ده إصدار مهم".

### إزاي تعمل Tag؟

```bash
git tag -a v1.0 -m "First Release Version"
```

- **`-a`**: يعني Annotated (فيها بيانات ومين اللي عملها).
    
- **`-m`**: الرسالة بتاعتك.
    

عشان ترفع الـ Tags للسيرفر (لأنها مش بتترفع مع `git push` العادية):

``` shell
git push --tags
```
