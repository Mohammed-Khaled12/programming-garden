03Networking
Virtual network (VNet)isolated private network, defined by a CIDR address space
Subnetsegments a VNet5 IPs always reserved (network, gateway, 2× DNS, broadcast)
VNet peeringVNet ↔ VNet over Microsoft's backbone, never the public internetnot transitive — A↔B↔C needs a direct A↔C peering
Site-to-Site VPNon-prem ↔ VNet, public internet, IPsec-encrypted
Point-to-Site VPNsingle device ↔ VNet, e.g. a laptop working from home
ExpressRouteprivate dedicated line via a connectivity provider, bypasses the public internet — predictable performance
Public endpointinternet-reachable address on a PaaS service
Private endpointactual NIC + private IP inside your subnet, via Azure Private Link
Network security group (NSG)L3-4 allow/deny rules on subnet or NICpriority 100–4096, lowest number wins; defaults sit at 65000+
Azure Firewallcentralized L3-7, FQDN filtering, threat intelligencelives in a dedicated AzureFirewallSubnet
DDoS ProtectionInfrastructure tier = free/automatic; Network/IP Protection = paid, SLA-backed

Conditional Accessif-this-then-that access rules (location, device, risk)
RBAC — core rolesOwner / Contributor / Reader / User Access Administratoradditive model — higher scope role still applies lower down
